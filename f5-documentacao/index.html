Módulo 1

Fundamentos do F5 BIG-IP

Conceitos essenciais que você precisa dominar antes de automatizar qualquer coisa no F5.

⚖

Virtual Server (VS)

Ponto de entrada do tráfego no F5. Recebe requisições dos clientes e direciona para o pool de servidores. Configurado com IP (VIP), porta, perfis e políticas.

☍

Pool & Pool Members

Grupo de servidores backend que atendem as requisições. O F5 distribui o tráfego entre os membros usando algoritmos de balanceamento (round-robin, least-connections, etc).

♥

Health Monitors

Verificações periódicas que o F5 faz nos backends para saber se estão saudáveis. Podem ser HTTP, TCP, ICMP ou customizados com send/receive strings.

🔒

SSL Offloading

O F5 termina a conexão SSL/TLS do cliente e se comunica com o backend via HTTP. Isso reduz carga nos servidores e centraliza a gestão de certificados.

🔌

SNAT (Source NAT)

Tradução do IP de origem para que o backend veja o IP do F5 (automap) ou de um SNAT pool. Essencial para garantir que a resposta volte pelo F5.

📋

Profiles

Configurações reutilizáveis (HTTP, TCP, SSL, Persistence, etc.) que definem como o F5 trata o tráfego. Cada VS pode ter múltiplos profiles.

Módulo 2

iRules — Programação no F5

iRules são scripts em TCL que rodam diretamente no data plane do F5, permitindo manipular tráfego em tempo real com performance extrema.

O que são iRules?
iRules são a linguagem de scripting nativa do F5 BIG-IP, baseada em TCL (Tool Command Language). Elas permitem inspecionar, modificar e redirecionar tráfego HTTP/HTTPS/TCP em tempo real, com acesso a headers, cookies, payloads e metadados da conexão. São executadas em eventos específicos do ciclo de vida da conexão.

Eventos Principais

Evento Quando dispara Uso comum
CLIENT_ACCEPTED Conexão TCP do cliente aceita Filtro por IP, rate limiting
HTTP_REQUEST Requisição HTTP recebida do cliente Redirecionamento, rewrite de URL, header manipulation
HTTP_RESPONSE Resposta HTTP recebida do backend Modificar headers de resposta, inserir cookies
LB_SELECTED Após o F5 selecionar o backend Logging, override de backend
LB_FAILED Falha ao conectar no backend Fallback, sorry page
CLIENTSSL_HANDSHAKE Handshake SSL completado Decisões baseadas em certificado do cliente

Exemplo 1: Redirect HTTP para HTTPS

TCL (iRule) redirect_https.tcl 
# iRule: Redirecionar todo tráfego HTTP para HTTPS
when HTTP_REQUEST {
    if { [HTTP::header "X-Forwarded-Proto"] eq "http" || [TCP::local_port] == 80 } {
        HTTP::redirect "https://[HTTP::host][HTTP::uri]"
    }
}

Exemplo 2: Roteamento por URI (Content Switching)

TCL (iRule) content_routing.tcl 
# iRule: Rotear tráfego para pools diferentes baseado na URI
when HTTP_REQUEST {
    switch -glob [HTTP::uri] {
        "/api/*" {
            # Requisições de API vão para o pool de microserviços
            pool pool_api_backend
            log local0. "[IP::client_addr] -> API: [HTTP::uri]"
        }
        "/static/*" -
        "/images/*" -
        "/css/*" {
            # Conteúdo estático vai para CDN/cache
            pool pool_static_content
        }
        "/admin/*" {
            # Painel admin - restringir por IP
            if { !([IP::client_addr] starts_with "10.10.") } {
                HTTP::respond 403 content "Acesso negado"
                return
            }
            pool pool_admin
        }
        "/health" {
            # Health check endpoint - responder direto sem ir ao backend
            HTTP::respond 200 content "OK" "Content-Type" "text/plain"
        }
        default {
            pool pool_app_principal
        }
    }
}

Exemplo 3: Rate Limiting por IP

TCL (iRule) rate_limit.tcl 
# iRule: Limitar requisições por IP (máximo 100 req/min)
when HTTP_REQUEST {
    set client_ip [IP::client_addr]
    set current_count [table lookup -notouch $client_ip]

    if { $current_count eq "" } {
        # Primeiro request deste IP - iniciar contador
        table set $client_ip 1 60
    } elseif { $current_count > 100 } {
        # Limite atingido - bloquear
        log local0. "RATE_LIMIT: IP $client_ip bloqueado ([HTTP::uri])"
        HTTP::respond 429 content "Rate limit exceeded. Try again later."
        return
    } else {
        # Incrementar contador
        table incr $client_ip
    }
}

Exemplo 4: Inserir Headers Customizados

TCL (iRule) custom_headers.tcl 
# iRule: Adicionar headers úteis para o backend
when HTTP_REQUEST {
    # Enviar IP real do cliente para o backend
    HTTP::header insert "X-Forwarded-For" [IP::client_addr]
    HTTP::header insert "X-Real-IP" [IP::client_addr]
    HTTP::header insert "X-Forwarded-Proto" "https"

    # Adicionar request ID para rastreabilidade
    HTTP::header insert "X-Request-ID" [TMM::cmp_unit][clock clicks]
}

when HTTP_RESPONSE {
    # Remover headers internos que não devem ser expostos
    HTTP::header remove "Server"
    HTTP::header remove "X-Powered-By"
    HTTP::header remove "X-AspNet-Version"

    # Adicionar headers de segurança
    HTTP::header insert "X-Content-Type-Options" "nosniff"
    HTTP::header insert "X-Frame-Options" "SAMEORIGIN"
    HTTP::header insert "Strict-Transport-Security" "max-age=31536000; includeSubDomains"
}

TCL (iRule) cookie_persistence.tcl 
# iRule: Persistência customizada por cookie com fallback
when HTTP_REQUEST {
    if { [HTTP::cookie exists "SERVERID"] } {
        set server_id [HTTP::cookie "SERVERID"]
        # Tentar direcionar para o servidor salvo no cookie
        if { [active_members pool_app_producao] > 0 } {
            pool pool_app_producao member $server_id 80
        }
    }
}

when HTTP_RESPONSE {
    # Inserir cookie com o IP do servidor selecionado
    if { !([HTTP::cookie exists "SERVERID"]) } {
        HTTP::cookie insert name "SERVERID" value [LB::server addr] path "/"
    }
}

Boas Práticas em iRules
  • Evite lógica complexa — iRules rodam no data plane, lógica pesada impacta performance
  • Use return cedo — saia da iRule o mais rápido possível
  • Prefira Local Traffic Policies para lógica simples — são mais eficientes que iRules
  • Teste em ambiente lab antes de colocar em produção
  • Use log local0. para debug, mas desabilite em produção
  • Evite HTTP::collect a menos que realmente necessário — consome memória

A API REST iControl permite gerenciar 100% do F5 BIG-IP programaticamente. Tudo que você faz na GUI ou tmsh pode ser feito via API.

Python 
import requests

# Autenticação por token - melhor performance e segurança
def obter_token(host, usuario, senha):
    url = f"https://{host}/mgmt/shared/authn/login"
    payload = {
        "username": usuario,
        "password": senha,
        "loginProviderName": "tmos"
    }
    resp = requests.post(url, json=payload, verify=False)
    resp.raise_for_status()
    token = resp.json()['token']['token']

    # Estender validade do token para 36000 segundos (10h)
    url_token = f"https://{host}/mgmt/shared/authz/tokens/{token}"
    requests.patch(url_token, json={"timeout": 36000},
                   headers={"X-F5-Auth-Token": token}, verify=False)

    return token

token = obter_token("192.168.1.245", "admin", "senha_segura")
headers = {"X-F5-Auth-Token": token, "Content-Type": "application/json"}

CRUD Completo: Pool + Members + Virtual Server

Python icontrol_crud.py 
import requests, urllib3, json
urllib3.disable_warnings()

class F5iControl:
    """Classe para interagir com iControl REST API do F5 BIG-IP."""

    def __init__(self, host, user, password):
        self.base = f"https://{host}/mgmt/tm"
        self.session = requests.Session()
        self.session.verify = False
        self.session.headers = {"Content-Type": "application/json"}
        self._authenticate(host, user, password)

    def _authenticate(self, host, user, password):
        url = f"https://{host}/mgmt/shared/authn/login"
        resp = requests.post(url, json={
            "username": user, "password": password,
            "loginProviderName": "tmos"
        }, verify=False)
        resp.raise_for_status()
        token = resp.json()["token"]["token"]
        self.session.headers["X-F5-Auth-Token"] = token

    # ===== POOLS =====
    def listar_pools(self):
        """GET /mgmt/tm/ltm/pool — Lista todos os pools."""
        resp = self.session.get(f"{self.base}/ltm/pool")
        return resp.json().get("items", [])

    def criar_pool(self, nome, lb_method="round-robin", monitor="/Common/http"):
        """POST /mgmt/tm/ltm/pool — Cria um novo pool."""
        payload = {"name": nome, "loadBalancingMode": lb_method, "monitor": monitor}
        resp = self.session.post(f"{self.base}/ltm/pool", json=payload)
        return resp.json()

    def deletar_pool(self, nome):
        """DELETE /mgmt/tm/ltm/pool/~Common~{nome}"""
        return self.session.delete(f"{self.base}/ltm/pool/~Common~{nome}")

    # ===== POOL MEMBERS =====
    def adicionar_membro(self, pool, ip, porta):
        """POST — Adiciona membro ao pool."""
        url = f"{self.base}/ltm/pool/~Common~{pool}/members"
        payload = {"name": f"{ip}:{porta}", "address": ip}
        return self.session.post(url, json=payload).json()

    def desabilitar_membro(self, pool, membro):
        """PATCH — Força membro offline (manutenção)."""
        url = f"{self.base}/ltm/pool/~Common~{pool}/members/~Common~{membro}"
        return self.session.patch(url, json={"session": "user-disabled", "state": "user-down"})

    def habilitar_membro(self, pool, membro):
        """PATCH — Habilita membro do pool."""
        url = f"{self.base}/ltm/pool/~Common~{pool}/members/~Common~{membro}"
        return self.session.patch(url, json={"session": "user-enabled", "state": "user-up"})

    # ===== VIRTUAL SERVERS =====
    def criar_virtual_server(self, nome, vip, porta, pool):
        """POST — Cria Virtual Server."""
        payload = {
            "name": nome,
            "destination": f"/Common/{vip}:{porta}",
            "pool": f"/Common/{pool}",
            "sourceAddressTranslation": {"type": "automap"},
            "profiles": [{"name": "http"}]
        }
        return self.session.post(f"{self.base}/ltm/virtual", json=payload).json()

    # ===== iRULES via API =====
    def criar_irule(self, nome, codigo_tcl):
        """POST — Cria iRule via API."""
        payload = {"name": nome, "apiAnonymous": codigo_tcl}
        return self.session.post(f"{self.base}/ltm/rule", json=payload).json()

    def associar_irule(self, vs_name, irule_name):
        """PATCH — Associa iRule ao Virtual Server."""
        url = f"{self.base}/ltm/virtual/~Common~{vs_name}"
        # Obter rules atuais
        current = self.session.get(url).json()
        rules = current.get("rules", [])
        rules.append(f"/Common/{irule_name}")
        return self.session.patch(url, json={"rules": rules})

    # ===== STATISTICS =====
    def obter_stats_vs(self, vs_name):
        """GET — Métricas do Virtual Server."""
        url = f"{self.base}/ltm/virtual/~Common~{vs_name}/stats"
        return self.session.get(url).json()


# ===== USO =====
f5 = F5iControl("192.168.1.245", "admin", "SenhaSegura")
f5.criar_pool("pool_web")
f5.adicionar_membro("pool_web", "10.10.1.10", 80)
f5.adicionar_membro("pool_web", "10.10.1.11", 80)
f5.criar_virtual_server("vs_web", "200.200.200.10", 443, "pool_web")

  • Debugging críptico

  • Sem idempotência nativa

Análise de Problemas Comuns no F5

Os problemas mais frequentes que você vai encontrar em produção, com diagnóstico e solução.

1. Pool Member Down

Sintoma
Membro do pool aparece com status vermelho (offline) na GUI ou via tmsh.
bash Diagnóstico 
# Verificar status do pool
tmsh show ltm pool pool_app_producao members

# Verificar monitor associado
tmsh list ltm pool pool_app_producao monitor

# Verificar logs do monitor
tail -f /var/log/ltm | grep pool_app_producao

# Testar conectividade com o servidor
curl -v http://10.10.1.10:80/health
CausaSolução
Serviço parado no backendsystemctl restart app
Firewall bloqueando health checkVerificar regras de FW entre F5 e backend
Monitor com send/receive incorretoAjustar string esperada no monitor
Timeout do monitorAumentar intervalo/timeout ou otimizar backend
Problema de rede (VLAN/rota)Verificar self IPs, VLANs e rotas

2. Virtual Server Não Responde

Sintoma
Usuários não conseguem acessar a aplicação via VIP. Timeout ou conexão recusada.
  • VS está enabled e available?
  • Pool tem membros available?
  • Perfil SSL correto e certificado válido?
  • SNAT configurado (automap ou snatpool)?
  • Regras de firewall permitem tráfego ao VIP?
  • DNS resolve para o IP correto do VIP?
  • Self IP e VLAN configurados corretamente?
  • Persistence profile está correto?
  • iRules não estão bloqueando tráfego?

3. Alta Utilização de CPU

Sintoma
F5 lento, dashboard mostrando CPU acima de 80%.
CausaSolução
iRules ineficientesOtimizar lógica, evitar regex complexo
Excesso de conexõesVerificar connection limits e timeouts
SSL handshakes excessivosImplementar SSL session reuse/caching
Ataque DDoSAtivar DoS protection profiles
Logging excessivoReduzir verbosidade

4. Persistência de Sessão Falha

Sintoma
Usuários perdem sessão/login durante navegação. Cada request vai para um backend diferente.
CausaSolução
Sem persistence profileAdicionar cookie ou source_addr persistence
Cookie com nome/path erradoVerificar configuração do cookie insert
Timeout muito curtoAumentar persistence timeout
Fallback não configuradoAdicionar fallback persistence (source_addr)

5. Certificado SSL Expirado

Sintoma
Navegador mostra erro de certificado. Conexões HTTPS falhando.
Python verificar_certs.py 
def verificar_certificados(f5, dias_alerta=30):
    """Verifica certificados próximos da expiração."""
    url = f"{f5.base}/sys/crypto/cert"
    certs = f5.session.get(url).json().get("items", [])

    for cert in certs:
        nome = cert.get("name", "unknown")
        expiration = cert.get("apiRawValues", {}).get("expiration", "")
        if expiration:
            from datetime import datetime
            exp_date = datetime.strptime(expiration, "%b %d %H:%M:%S %Y %Z")
            dias = (exp_date - datetime.now()).days
            if dias <= dias_alerta:
                nivel = "CRITICO" if dias <= 7 else "ALERTA"
                print(f"[{nivel}] {nome} expira em {dias} dias")

WAF / ASM — Web Application Firewall

Proteja suas aplicações contra SQL Injection, XSS, bots e outros ataques na camada 7.

O que o WAF Protege?

🔒

SQL Injection

Bloqueia tentativas de injeção SQL em formulários, URLs e parâmetros. 200+ assinaturas de detecção.

⚠

Cross-Site Scripting (XSS)

Detecta e bloqueia scripts maliciosos em campos de entrada, impedindo roubo de sessões.

💻

Command Injection

Previne execução de comandos do sistema operacional via parâmetros da aplicação.

🤖

Bot Defense

Identifica e bloqueia bots maliciosos, scrapers e ferramentas de scanning. CAPTCHA para bots desconhecidos.

🕵

Data Guard

Mascara dados sensíveis (CPF, cartão de crédito) nas respostas HTTP. Previne vazamento de dados.

🛠

Protocol Compliance

Verifica conformidade com RFCs do HTTP. Bloqueia requisições malformadas e tentativas de evasão.

Fluxo de Implementação

1. Provisionar Módulo ASM

tmsh modify sys provision asm level nominal

2. Criar Security Policy (Rapid Deployment)

Comece com o template Rapid Deployment — menor risco de falsos positivos.

3. Modo Transparent (2-4 semanas)

Módulo 7

Caso Real: Monitoramento + Automação para Recuperação

Como uma empresa de e-commerce reduziu o MTTR de 18 minutos para 2.5 minutos usando automação F5.

O Cenário

🏭

Infraestrutura

F5 BIG-IP como load balancer principal, pool com 6 servidores (3 por DC), aplicação crítica de checkout.

💥

O Problema

Black Friday: 2 de 3 servidores do DC primário caíram por estouro de memória. Response time subiu para 8s.

💰

Impacto

R$ 50.000/minuto em vendas perdidas. NOC levou 12 minutos para agir manualmente. Perda total: R$ 600.000+.

Arquitetura da Solução

Fluxo de Recuperação Automática

1. Detectar membros down

Zabbix detecta que o pool tem menos de 2 membros disponíveis. Aciona webhook.

2. Tentar reiniciar serviços

Script Python conecta via SSH nos backends problemáticos e reinicia o serviço (até 3 tentativas).

3. Verificar recuperação

Aguarda 15 segundos e verifica via health check direto se o backend voltou.

4. Ativar servidores standby

Se os primários não voltaram, ativa servidores standby do outro DC via API do F5.

5. Redistribuir carga

Aumenta connection limit dos membros saudáveis para absorver o tráfego extra.

6. Notificar equipe

Envia relatório completo para Slack com status final e membros que precisam de atenção manual.
